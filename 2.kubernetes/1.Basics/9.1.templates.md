In a Kubernetes YAML file, `template`**&#x20;represents the blueprint for creating Pods.**

It defines how Kubernetes should create and configure the Pods managed by a Deployment.

### **Example**

```
apiVersion: apps/v1
kind: Deployment
metadata:
  name: webapp
spec:
  replicas: 2
  selector:
    matchLabels:
      app: webapp

  template:                 # Pod template
    metadata:
      labels:
        app: webapp

    spec:
      containers:
        - name: webapp
          image: my-webapp:1.0
          ports:
            - containerPort: 8080
```

### **What does each section represent?**

| Section             | Purpose                            |
| ------------------- | ---------------------------------- |
| `template`          | Blueprint for creating Pods        |
| `template.metadata` | Pod metadata, such as labels       |
| `template.spec`     | Pod configuration                  |
| `containers`        | Containers running inside the Pod  |
| `image`             | Docker image used by the container |

### **How it works**

1. You create a Deployment with `replicas: 2`.
2. Kubernetes reads the `template`.
3. It creates two Pods using that template.
4. Both Pods get the same container configuration.
5. If a Pod crashes, Kubernetes creates a replacement using the same template.

**Important points:**

- `Deployment.spec.template` defines the Pod specification.
- `template` is not a separate Kubernetes resource.
- Every Pod created by that Deployment follows this template.
- If you modify the Pod template (for example, change the image version), Kubernetes triggers a rolling update.

**In simple terms:** `template` = Blueprint; `Pod` = Actual instance created from that blueprint.

## **Labels in Kubernetes**

**What are Labels?**

Labels are key-value pairs attached to Kubernetes resources (Pods, Deployments, Services, etc.) to identify and organize them.

### **Why do we need Labels?**

- **Identification:** Identify resources based on application or environment.
- **Grouping:** Group related resources.
- **Selection:** Allow Services and Deployments to select specific Pods.
- **Management:** Filter and manage resources easily.

### **Example**

```
metadata:
  labels:
    app: product-api
    environment: development
```

A Service can use these labels to identify which Pods should receive traffic.

```
selector:
  app: product-api
```

### **Useful Command**

```
kubectl get pods --show-labels

kubectl get pods -l app=product-api
```

**In simple words:** Labels help organize, identify, group, and select Kubernetes resources.

---

`matchLabels` is used in a Deployment's `selector` to identify Pods based on their labels.

It ensures the Deployment manages only Pods with matching labels.

```
selector:
  matchLabels:
    app: product-api
```

This matches Pods having:

```
labels:
  app: product-api
```

**In simple words:** `matchLabels` connects a Deployment to the Pods it should manage.

### **Important Service YAML attributes**

| Attribute         | Purpose                                                 |
| ----------------- | ------------------------------------------------------- |
| `apiVersion`      | API version (`v1`).                                     |
| `kind`            | Resource type (`Service`).                              |
| `metadata.name`   | Service name.                                           |
| `metadata.labels` | Labels for identifying the Service.                     |
| `spec.type`       | Service type (`ClusterIP`, `NodePort`, `LoadBalancer`). |
| `selector`        | Matches Service with Pod labels.                        |
| `port`            | Service communication port.                             |
| `targetPort`      | Application port inside the Pod.                        |
| `nodePort`        | External Node port (NodePort only).                     |

**Remember:**

- `port` → Service port.
- `targetPort` → Container port.
- `nodePort` → Node's external port.

**Kubernetes NodePort default range:** `30000–32767`

Example:

```
nodePort: 30080
```

You can configure a different range in the Kubernetes API Server using `--service-node-port-range`.
