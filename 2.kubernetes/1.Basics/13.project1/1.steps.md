# **Kubernetes Practical Project: Spring Boot + MongoDB**

We will build a simple **Product Management REST API** using Spring Boot, MongoDB, Docker, and Kubernetes.

The project will demonstrate how a real application connects to a database inside a Kubernetes cluster.



Hands-on project

Minikube + Docker



## **1. What we are going to build**

A Spring Boot application that performs basic database operations:

- Add a product.
- Get all products.
- Get a product by ID.
- Delete a product.

**Technology stack**

| Java 21             | Backend programming         |
| Spring Boot         | REST API                    |
| Spring Data MongoDB | Database connectivity       |
| MongoDB             | Database                    |
| Docker              | Build application image     |
| Minikube            | Local Kubernetes cluster    |
| kubectl             | Manage Kubernetes resources |

## **4. Develop the Spring Boot application**

### **Step 1: Create Product model**

`model/Product.java`

```
package com.example.productapi.model;

import org.springframework.data.annotation.Id;
import org.springframework.data.mongodb.core.mapping.Document;

@Document(collection = "products")
public class Product {

    @Id
    private String id;

    private String name;
    private double price;

    public Product() {
    }

    public Product(String name, double price) {
        this.name = name;
        this.price = price;
    }

    public String getId() {
        return id;
    }

    public void setId(String id) {
        this.id = id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public double getPrice() {
        return price;
    }

    public void setPrice(double price) {
        this.price = price;
    }
}
```

### **Step 2: Create Repository**

`repository/ProductRepository.java`

```
package com.example.productapi.repository;

import org.springframework.data.mongodb.repository.MongoRepository;
import com.example.productapi.model.Product;

public interface ProductRepository
        extends MongoRepository<Product, String> {
}
```

**Purpose:** MongoRepository provides built-in database operations such as save, findAll, findById, and deleteById.

### **Step 3: Create Controller**

`controller/ProductController.java`

```
package com.example.productapi.controller;

import java.util.List;

import org.springframework.web.bind.annotation.*;

import com.example.productapi.model.Product;
import com.example.productapi.repository.ProductRepository;

@RestController
@RequestMapping("/api/products")
public class ProductController {

    private final ProductRepository repository;

    public ProductController(ProductRepository repository) {
        this.repository = repository;
    }

    // Add product
    @PostMapping
    public Product addProduct(@RequestBody Product product) {
        return repository.save(product);
    }

    // Get all products
    @GetMapping
    public List<Product> getProducts() {
        return repository.findAll();
    }

    // Get product by ID
    @GetMapping("/{id}")
    public Product getProduct(@PathVariable String id) {
        return repository.findById(id).orElse(null);
    }

    // Delete product
    @DeleteMapping("/{id}")
    public void deleteProduct(@PathVariable String id) {
        repository.deleteById(id);
    }
}
```

### **Step 4: Configure application.properties**

`src/main/resources/application.properties`

```
spring.application.name=product-api

spring.data.mongodb.host=${MONGO_HOST:localhost}
```

**Important:**

### **Step 1: ConfigMap**

`k8s/mongodb-configmap.yaml`

Stores non-sensitive MongoDB configuration.

```
apiVersion: v1
kind: ConfigMap
metadata:
  name: mongodb-config

data:
  MONGO_HOST: mongodb
  MONGO_PORT: "27017"
  MONGO_DATABASE: productdb
```

Explanation:

| Variable       | Value     | Purpose              |
| -------------- | --------- | -------------------- |
| MONGO_HOST     | mongodb   | MongoDB Service name |
| MONGO_PORT     | 27017     | MongoDB port         |
| MONGO_DATABASE | productdb | Database name        |

Both MongoDB and Spring Boot can use this configuration.

### **Step 2: Secret**

`k8s/mongodb-secret.yaml`

Stores MongoDB credentials.

```
apiVersion: v1
kind: Secret
metadata:
  name: mongodb-secret

type: Opaque

stringData:
  MONGO_USERNAME: admin
  MONGO_PASSWORD: ChangeMe123!
```

Explanation:

- `stringData` allows us to provide plain text values in the YAML.
- Kubernetes converts these values into its Secret data representation.
- We will inject these credentials into both MongoDB and Spring Boot containers.

**Security note:** Base64 encoding is not encryption. These credentials are only for local practice. Enable encryption at rest and restrict Secret access in real environments. Don't commit real credentials to Git.

### **Step 3: PersistentVolumeClaim (PVC)**

`k8s/mongodb-pvc.yaml`

We need persistent storage for MongoDB data.

```
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mongodb-pvc

spec:
  accessModes:
    - ReadWriteOnce

  resources:
    requests:
      storage: 1Gi
```

Explanation:

- Requests 1 GB of storage.
- Kubernetes provisions storage through the available StorageClass.
- MongoDB mounts this storage at `/data/db`.
- Data can survive MongoDB Pod replacement as long as the PVC and underlying storage remain intact.

### **Step 4: MongoDB Deployment**

`k8s/mongodb-deployment.yaml`

This creates a MongoDB Pod.

```
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mongodb

spec:
  replicas: 1

  selector:
    matchLabels:
      app: mongodb

  template:
    metadata:
      labels:
        app: mongodb

    spec:
      containers:
        - name: mongodb
          image: mongo:7.0

          ports:
            - containerPort: 27017

          env:
            - name: MONGO_INITDB_DATABASE
              valueFrom:
                configMapKeyRef:
                  name: mongodb-config
                  key: MONGO_DATABASE

            - name: MONGO_INITDB_ROOT_USERNAME
              valueFrom:
                secretKeyRef:
                  name: mongodb-secret
                  key: MONGO_USERNAME

            - name: MONGO_INITDB_ROOT_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: mongodb-secret
                  key: MONGO_PASSWORD

          volumeMounts:
            - name: mongodb-storage
              mountPath: /data/db

          readinessProbe:
            tcpSocket:
              port: 27017
            initialDelaySeconds: 10
            periodSeconds: 5

          livenessProbe:
            tcpSocket:
              port: 27017
            initialDelaySeconds: 30
            periodSeconds: 10

      volumes:
        - name: mongodb-storage
          persistentVolumeClaim:
            claimName: mongodb-pvc
```

**Important points:**

- `replicas: 1` creates one MongoDB Pod.
- `MONGO_INITDB_ROOT_USERNAME` and `MONGO_INITDB_ROOT_PASSWORD` initialize the MongoDB root user on the first database initialization.
- `volumeMounts` connects persistent storage to MongoDB.
- `readinessProbe` checks whether MongoDB is accepting TCP connections.
- `livenessProbe` checks whether the MongoDB process is responding on its port.

### **Step 5: MongoDB Service**

`k8s/mongodb-service.yaml`

This provides a stable internal endpoint for MongoDB.

```
apiVersion: v1
kind: Service
metadata:
  name: mongodb

spec:
  type: ClusterIP

  selector:
    app: mongodb

  ports:
    - port: 27017
      targetPort: 27017
```

**Why ClusterIP?**

MongoDB is only required by the Spring Boot application inside the Kubernetes cluster. We don't need to expose it publicly.

The Spring Boot application will connect using:

```
mongodb:27017
```

Here, `mongodb` is the Kubernetes Service DNS name.

## **7. Create Spring Boot Kubernetes files**

### **Step 1: Web Application Deployment**

`k8s/webapp-deployment.yaml`

This creates the Spring Boot application Pod.

```
apiVersion: apps/v1
kind: Deployment
metadata:
  name: product-api

spec:
  replicas: 1

  selector:
    matchLabels:
      app: product-api

  template:
    metadata:
      labels:
        app: product-api

    spec:
      initContainers:
        - name: wait-for-mongodb
          image: busybox:1.36
          command:
            - sh
            - -c
            - until nc -z mongodb 27017; do echo "Waiting for MongoDB"; sleep 2; done

      containers:
        - name: product-api
          image: product-api:v1
          imagePullPolicy: IfNotPresent

          ports:
            - containerPort: 8080

          envFrom:
            - configMapRef:
                name: mongodb-config

            - secretRef:
                name: mongodb-secret

          readinessProbe:
            tcpSocket:
              port: 8080
            initialDelaySeconds: 15
            periodSeconds: 5

          livenessProbe:
            tcpSocket:
              port: 8080
            initialDelaySeconds: 30
            periodSeconds: 10
```

**Important points:**

- `initContainers` waits until MongoDB accepts TCP connections.
- `image` specifies our Spring Boot Docker image.
- `envFrom` injects ConfigMap and Secret values as environment variables.
- `containerPort: 8080` is the Spring Boot application port.

Our `application.properties` automatically reads these environment variables.

### **Step 2: Web Application Service**

`k8s/webapp-service.yaml`

We want to access Spring Boot from outside Kubernetes.

```
apiVersion: v1
kind: Service
metadata:
  name: product-api-service

spec:
  type: NodePort

  selector:
    app: product-api

  ports:
    - port: 8080
      targetPort: 8080
      nodePort: 30080
```

**Why NodePort?**

It exposes the application through a port on the Kubernetes Node, allowing us to access it from outside the cluster.

## **13. Understand the complete flow**

When you send a POST request to add a product:

1. Request reaches the Product Service.
2. Service forwards the request to the Spring Boot Pod.
3. ProductController receives the request.
4. ProductRepository saves the product.
5. Spring Boot uses the MongoDB configuration from ConfigMap.
6. MongoDB username and password come from Secret.
7. Spring Boot connects to the MongoDB Service (`mongodb:27017`).
8. MongoDB stores the product in its database.
9. Spring Boot returns the response.

**Important:** MongoDB Service provides internal communication. Product API Service provides external access.

## **14. Troubleshooting common issues**

| Problem                    | Possible solution                                              |
| -------------------------- | -------------------------------------------------------------- |
| ImagePullBackOff           | Check image name and run `minikube image load product-api:v1`. |
| CrashLoopBackOff           | Check application logs using `kubectl logs`.                   |
| PVC Pending                | Check `kubectl get storageclass` and PVC events.               |
| MongoDB connection refused | Check MongoDB Pod and Service.                                 |
| Authentication failed      | Verify username, password, and authentication database.        |
| Spring Boot Pod waiting    | Check MongoDB Service and Pod readiness.                       |

**Important MongoDB note:** `MONGO_INITDB_ROOT_USERNAME` and `MONGO_INITDB_ROOT_PASSWORD` initialize credentials only when MongoDB initializes an empty data directory. Changing the Kubernetes Secret later does not automatically change an existing MongoDB user's password.

### **Important interview questions**

**1. Why do we use ConfigMap?**

To store non-sensitive configuration separately from application code.

**2. Why do we use Secret?**

To store sensitive information such as passwords and API keys.

**3. Why do we use ClusterIP for MongoDB?**

Because MongoDB only needs to communicate with applications inside the Kubernetes cluster.

**4. Why do we use NodePort for Spring Boot?**

To access the Spring Boot application from outside the cluster.

**5. Why do we use PVC?**

To preserve MongoDB data beyond the lifecycle of an individual Pod.

**6. How does Spring Boot connect to MongoDB?**

Through the MongoDB Service DNS name and port (`mongodb:27017`).

**7. Why do we use Deployment?**

To manage Pods, maintain replicas, and automatically replace failed Pods.

**8. Why do we load the Docker image into Minikube?**

So Kubernetes can access our locally built application image without downloading it from a remote registry.

## **17. Important real-world considerations**

This project uses a MongoDB Deployment with one replica to keep the learning process simple.

In production:

- Prefer StatefulSet for self-managed stateful databases that need stable identities.
- Use reliable persistent storage and backups.
- Avoid exposing MongoDB publicly.
- Use proper Secret management and encryption.
- Consider managed MongoDB services when database operations need to be simplified.
