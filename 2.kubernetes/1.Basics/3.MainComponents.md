# **Kubernetes Components – Description and Role**

Kubernetes components are divided into two major categories: **Control Plane** and **Worker Node**.

## **1. Control Plane Components**

The Control Plane manages the entire Kubernetes cluster and maintains its desired state.

| Component              | Description & Role                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------- |
| **API Server**         | Entry point of Kubernetes. Receives and processes requests from users and other components. |
| **Scheduler**          | Selects the appropriate Worker Node to run newly created Pods.                              |
| **Controller Manager** | Continuously monitors the cluster and ensures the actual state matches the desired state.   |
| **etcd**               | Key-value database that stores Kubernetes cluster configuration and state information.      |

## **2. Worker Node Components**

A **Node** is a physical or virtual machine that runs application workloads (Pods).

Each Worker Node contains the following components:

| Component             | Description & Role                                                                                |
| --------------------- | ------------------------------------------------------------------------------------------------- |
| **Kubelet**           | Communicates with the API Server and ensures assigned Pods and containers are running properly.   |
| **Kube-proxy**        | Handles network rules and routes Service traffic to appropriate Pods.                             |
| **Container Runtime** | Responsible for downloading container images and running containers. Examples: containerd, CRI-O. |

## **3. Kubernetes Objects**

These are resources used to deploy and manage applications inside Kubernetes.

| Component      | Description & Role                                                       |
| -------------- | ------------------------------------------------------------------------ |
| **Pod**        | Smallest deployable unit in Kubernetes. Contains one or more containers. |
| **Deployment** | Manages Pod replicas, scaling, and rolling updates.                      |
| **ReplicaSet** | Ensures the required number of Pod replicas are running.                 |
| **Service**    | Provides a stable IP address and DNS name to access Pods.                |
| **ConfigMap**  | Stores non-sensitive application configuration.                          |
| **Secret**     | Stores sensitive information such as passwords and tokens.               |
| **Ingress**    | Manages external HTTP/HTTPS access to applications inside the cluster.   |
| **Namespace**  | Logically separates and organizes resources within a cluster.            |

## **4. How everything works together**

Example: Deploying a Spring Boot application.

1. **Deployment:** You request 3 replicas of your Spring Boot application.
2. **API Server:** Receives the deployment request.
3. **etcd:** Stores the cluster state.
4. **Controller Manager:** Ensures the required ReplicaSet and Pods are created.
5. **Scheduler:** Selects suitable Worker Nodes for the Pods.
6. **Kubelet:** Ensures the assigned Pods are running.
7. **Container Runtime:** Starts the Spring Boot containers.
8. **Service:** Provides a stable endpoint to access the Pods.

## **Quick revision**

| Category           | Main Components                                                             |
| ------------------ | --------------------------------------------------------------------------- |
| Control Plane      | API Server, Scheduler, Controller Manager, etcd                             |
| Worker Node        | Node, Kubelet, Kube-proxy, Container Runtime                                |
| Kubernetes Objects | Pod, Deployment, ReplicaSet, Service, ConfigMap, Secret, Ingress, Namespace |

**Important interview points:**

- Cluster = Collection of Control Plane and Worker Nodes.
- Node = Machine where workloads run.
- Pod = Smallest deployable unit.
- Deployment = Manages application Pods.
- Service = Provides stable network access.
- Kubelet = Manages Pods on a Worker Node.
- etcd = Stores cluster state.
