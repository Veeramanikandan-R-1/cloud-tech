## **1. Deployment in Kubernetes**

**What is it?**

Deployment manages stateless applications by creating and maintaining the required number of Pod replicas.

### **Why do we need it?**

- Creates and manages multiple Pod replicas.
- Automatically replaces failed Pods.
- Supports scaling applications.
- Supports rolling updates and rollbacks.

**Example:** React frontend or Spring Boot REST API, where any Pod can handle any request.

## **2. StatefulSet in Kubernetes**

**What is it?**

StatefulSet manages stateful applications where each Pod needs a stable identity and persistent storage.

### **Why do we need it?**

- Maintains stable Pod names and identities.
- Provides stable network identities.
- Maintains persistent storage for individual Pods.
- Supports ordered Pod creation and deletion.

**Example:** MySQL, MongoDB, or Kafka clusters.

## **3. Deployment vs StatefulSet**

| Deployment                                         | StatefulSet                                    |
| -------------------------------------------------- | ---------------------------------------------- |
| Used for stateless applications.                   | Used for stateful applications.                |
| Pods are interchangeable.                          | Each Pod has a unique identity.                |
| Pod names are not predictable across replacements. | Pod names remain stable.                       |
| Storage is not automatically dedicated per Pod.    | Supports dedicated persistent storage per Pod. |
| No guaranteed ordered deployment.                  | Supports ordered deployment and termination.   |

**In simple words:**

- Deployment → Manages interchangeable Pods.
- StatefulSet → Manages Pods that need stable identities and storage.

**Interview example:**

- React / Spring Boot → Deployment.
- MySQL / MongoDB → StatefulSet.

## **Why are databases usually hosted outside Kubernetes?**

Databases are often hosted externally (AWS RDS, Azure SQL, etc.) instead of inside Kubernetes because **databases require reliable, persistent storage and careful management.**

### **Main Reasons**

1\. **Data Persistence:** Databases need reliable storage that must survive Pod and Node failures.

2\. **Complexity:** Managing database backups, replication, recovery, and upgrades inside Kubernetes requires additional effort.

3\. **High Availability:** Managed database services provide built-in replication and failover mechanisms.

4\. **Performance:** External database services can provide dedicated storage and compute resources.

5\. **Maintenance:** Cloud providers manage database patching, backups, monitoring, and maintenance.

6\. **Data Safety:** Separating databases from application workloads reduces operational risks during application deployments.

### **Example**

Suppose you have an application:

- React frontend → Kubernetes
- Spring Boot backend → Kubernetes
- MySQL database → AWS RDS

The Spring Boot application connects to MySQL through its database endpoint.

### **Can databases run inside Kubernetes?**

**Yes.** Kubernetes supports databases using StatefulSets and PersistentVolumes.

However, managing them requires additional configuration and operational expertise.

**In simple words:** Applications are commonly deployed in Kubernetes, while databases are often hosted externally to simplify data management, improve reliability, and reduce operational complexity.
